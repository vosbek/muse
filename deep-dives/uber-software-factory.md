# Uber: Running a Software Factory Efficiently at Uber Scale

**What it is.** Uber Engineering's public cost-control playbook, published 2026-08-27 by Distinguished Engineer Uday Kiran Medisetty. It's the first Fortune-500-scale account of running coding agents in production with the actual numbers attached — and it's the single best reference for Matt's tokenomics remit.

**Key numbers.** >70% of pull requests attributed to local or cloud agents. Engineers built **3,600+ agent skills** across the SDLC, executing **30K+ skill executions/day**. Feb→Aug 2026: **7x weekly active users, 9.4x weekly agent requests — while total AI spend stabilized since April**. With the model held constant: **cost per 1,000 requests down ~34% from peak, cost per session down 52%** from the June peak.

**How they did it — the cost equation.** Total spend = users × sessions/user × turns/session × requests/turn × tokens/request × price/token. Each term is measured and shrunk independently; the middle three (the agent's own overhead, on top of what the engineer asked for) get most of the effort. The levers:

- **Price/token — benchmark-driven, Pareto-optimal model selection.** Every managed agent gets a benchmark built from *its real work*; models are tested behind one harness interface and moved to whatever is Pareto-optimal on cost-per-completed-task vs quality. Example: uReview (AI code review for all PRs) benchmarked on real PRs with known bugs graded easy/medium/hard, scoring precision/recall/F1 plus cost/review — switching models improved F1 *while* cutting cost/PR. Subagents default to weaker models (they do well-defined work that rarely needs frontier reasoning); the primary model decomposes and evaluates.
- **Tokens/request — the context layer.** Auto-compaction at **400K tokens even for 1M-context models** (balances performance vs cache-burst rebuild costs). **Reasoning effort defaulted to Medium** (output/reasoning tokens are billed at multiples of input). **Prompt caching with 1-hour TTL** for main sessions (engineers idle >5 min, which was invalidating 5-min caches and forcing full-price rebuilds); subagents keep 5-min TTL. **MCP tools resolved via CLI + tool search** instead of preloading schemas: 100+ tools were adding **50–70K tokens of schema overhead to every turn** — eliminated. **Code-mode batching**: a SQL query that took 5 model turns (submit, poll 2–5x, fetch) becomes one Python loop in a subprocess with only the summary returning — measured **55–100% token savings** per query (a wide `SELECT *` went from 1,431,594 tokens to 900).
- **Requests/turn — graph-grounded context** (AI Context Graph) and continuous skill optimization from execution traces.
- **Visibility.** Live cost counter in the status line, spend tiers, and a session-analysis dashboard that auto-flags 16 categories of wasted spend (idle-cache rebuilds, oversized tool responses, etc.).

**Why it matters for tokenomics / context management.** This is the enterprise operating model in one article: decompose spend multiplicatively, instrument every term, optimize cost-per-*completed task* (not per token), and treat context as the primary cost surface — compaction thresholds, cache TTLs matched to real idle behavior, and killing the MCP schema tax. The "middle three terms" framing is directly portable: most enterprise agent spend is the agent's own overhead, and that's where the levers are. The dashboard-of-waste-patterns idea is the cheapest thing to copy first.
