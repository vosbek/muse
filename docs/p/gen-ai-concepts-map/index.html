90 Gen AI Concepts — the Playbook's Living Index

Source: @datasciencebrain (Deepak Jose, ~485K followers), Oct 18, 2026 — a carousel of "90 Concepts Asked In 99% of GenAI Interviews," arranged in the order interviews tend to go. This page turns his five bands into five permanent sections: each section holds the concepts, the original slide infographics, and the playbook articles that cover them. New pieces get filed under their section as they arrive.

He gates the in-depth book ("Gen AI: Zero to Hero," ₹199) behind a "comment HERO" DM — what's below is the map itself, rebuilt from the public carousel.

1 · LLM fundamentals & working with models (1–20)

  1. Tokenization — text split into tokens; the unit of cost, speed, and context limits.
  2. Embeddings — text as vectors; similar meanings sit close together.
  3. Attention & Transformers — every token weighs every other token to decide what matters.
  4. Context Window — everything sent in one call. Not memory.
  5. KV Cache — cached attention states during generation; caps how many users one GPU serves.
  6. Temperature & Top-p — sampling controls for how random the next token is.
  7. Hallucination — fluent output with nothing behind it; no internal truth check.
  8. Reasoning Models — models that spend extra "thinking" tokens first; better on hard tasks, slower and pricier.
  9. Mixture of Experts — each token routes to a few expert sub-networks; huge but cheap to run.
  10. TTFT — time to first token; what makes an app feel fast.

  1. Structured Output — constrain answers to a schema, then validate.
  2. Tool Calling — the model requests a tool, your code runs it, the result goes back in.
  3. Parallel Tool Calls — multiple tool calls in one turn, matched by call ID.
  4. Prompt Caching — reuse the static prompt prefix at a discount.
  5. Model Routing — cheap model for easy requests, strong model for hard ones.
  6. Batch API — deferred requests processed later, cheaper.
  7. Local Models — open weights running on your own hardware.
  8. Prompt vs Context Engineering — how you ask vs. what the model gets to see.
  9. Few-Shot Prompting — examples in the prompt to set format and tone.
  10. Token Budgets — hard per-section token caps, enforced in code.

2 · Context, backend & RAG (21–40)

  1. Lost in the Middle — models favor the start and end; put key facts at an edge.
  2. Conversation Compression — summarize old turns, keep recent ones verbatim.
  3. Memory Types — episodic (events), semantic (facts), procedural (how-to).
  4. Context Rot — stale context piling up makes answers generic.
  5. Context Poisoning — one wrong fact in context, reused forever.
  6. Multi-Tenancy — many customers, strict data isolation between them.
  7. Graceful Degradation — fall back step by step on provider failure; never invent.
  8. Idempotency Keys — retry-safe IDs so repeats don't double-apply.
  9. Circuit Breakers — stop calling a service that's repeatedly failing.
  10. Canary Deploys — roll out to a slice first, then widen.

  1. Chunking — split docs into retrievable pieces sized to the questions.
  2. Vector Databases & HNSW — fast approximate similarity search.
  3. Dense vs Sparse Retrieval — meaning search vs keyword (BM25) search.
  4. Hybrid Search & RRF — fuse both rankings by reciprocal rank.
  5. Reranking — a slower, sharper model reorders the shortlist.
  6. Query Rewriting & HyDE — fix vague queries; search with a hypothetical answer.
  7. Grounding & Citations — every claim tied to a retrieved source.
  8. Refusal Thresholds — below a relevance floor, answer "I don't know."
  9. Contextual Retrieval — embed chunks with their document/section context attached.
  10. Matryoshka Embeddings — embeddings that stay useful when truncated.

3 · Advanced RAG, agents, MCP & judges (41–60)

  1. Recall@k & MRR — did the right chunk make the top k, and how high?
  2. Golden Sets — hand-labeled Q&A with known-correct sources.
  3. Multi-Hop Retrieval — search again using what the first search found.
  4. GraphRAG — retrieval over entity/relationship graphs; usually premature.
  5. Agentic RAG — the model drives retrieval: fetch, check, fetch again.
  6. Multimodal RAG — retrieve over images and tables, not just text.
  7. RAG vs Fine-tuning vs Long Context — changing facts → RAG; behavior → fine-tune; one-off docs → long context.
  8. Workflow vs Agent — fixed steps in code vs the model choosing the next step.
  9. ReAct vs Plan-and-Execute — think-act-observe loop vs plan-then-execute.
  10. Compounding Reliability — 95% per step × 20 steps ≈ 36% end-to-end.

  1. Agent Failure Modes — loops, silent tool failures, wandering, context overflow, false "done."
  2. Loop Detection — catch repeated no-progress calls and stop them.
  3. Human-in-the-Loop — pause for approval before risky actions.
  4. Multi-Agent Systems — several agents collaborating; every handoff loses context.
  5. Orchestrator-Worker — one planner delegates to specialist workers.
  6. MCP — the open protocol connecting AI apps to tools, resources, prompts.
  7. A2A — protocol for agents across organizations to delegate work.
  8. LLM-as-Judge — one model grading another's answers.
  9. Judge Calibration — validate the judge against human labels (Cohen's kappa).
  10. Statistical Significance — is the score delta real or noise? (McNemar's test.)

4 · Evals, security & fine-tuning (61–80)

  1. Traces & Spans — per-request record of model calls, retrieval, tools.
  2. Evals in CI — quality tests that block merges on regression.
  3. Faithfulness — does the answer stick to its sources?
  4. Position Bias — judges favor whichever answer is shown first.
  5. Pairwise Comparison — the judge picks the better of two instead of scoring one.
  6. Cost per Success — total spend ÷ successful tasks, not ÷ calls.
  7. Prompt Injection — malicious instructions hidden in data.
  8. Indirect Injection — injection arriving via documents, email, web pages.
  9. Lethal Trifecta — private data + untrusted content + an outbound channel = leak.
  10. Excessive Agency — the system can do more than it should.

  1. Exfiltration — private data leaving through an outbound channel.
  2. Dual-LLM Pattern — a tool-less quarantined model reads untrusted text; the main model sees only its output.
  3. PII in Prompts & Logs — redact personal data before it lands in traces.
  4. Red Teaming — attack your own system deliberately; keep the attacks as CI tests.
  5. OWASP LLM Top 10 — the standard LLM app risk list.
  6. When to Fine-tune — for behavior and format, never for facts.
  7. LoRA & QLoRA — train a small adapter on a frozen model; QLoRA shrinks the base to 4-bit.
  8. DPO — learn from preferred-vs-rejected answer pairs.
  9. GRPO — RL that compares a group of answers to the same prompt.
  10. Reward Hacking — the model games the reward instead of doing the task.

5 · Inference & serving (81–90)

  1. Catastrophic Forgetting — fine-tuning eroding general ability.
  2. Quantization & Distillation — lower-precision weights; small model taught by big one.
  3. Prefill vs Decode — reading the prompt vs emitting tokens; decode is memory-bandwidth-bound.
  4. Continuous Batching — new requests join as others finish; GPU stays busy.
  5. PagedAttention — KV cache in pages, less memory wasted.
  6. Speculative Decoding — small model drafts, big model verifies several tokens at once.
  7. Prefix Caching — reuse cached compute for shared prompt prefixes.
  8. Grouped-Query Attention — attention heads share KV data; smaller cache.
  9. Self-Hosting vs API — self-hosting wins only at high, steady usage.
  10. Voice Agents — STT → LLM → TTS inside a tight latency budget.
