Talk Notes: "Get Out of the Model's Way" — Kevin Hou, Google Antigravity

Video: Get Out of the Model's Way — Kevin Hou, Google Antigravity · AI Engineer channel · Sep 27, 2026 · 19:00 · Recorded at AI Engineer World's Fair 2026

Note: YouTube's transcript was unreadable in our environment, so this is distilled from the video's own description/chapters plus biggo.com's AI-generated talk summary — treat secondary-derived points as the speaker's arguments per those summaries, not verbatim transcript.

Thesis

"Scaling with intelligence" — product architecture should be a function of model capability, not a fixed design. Builders should remove beloved-but-obsolete primitives (chat sidebars, fixed IDEs, hand-written UIs) and ship primitives that get better as models do: dynamic subagents, sidecar triggers, and generative UI. Evidence: 93 subagents built a from-scratch OS kernel running Doom in 12 hours for under $1,000 (2B tokens), and DeepMind researchers automated 90% of side-by-side eval analysis with agent teams — while the "human-written specialized UI" is declared "kind of dead."

Key points

  • Framing: coaching Argentina in the 89th minute with Messi on the pitch — "give Messi the ball and get the heck out of the way." LLMs are no longer role players; they can be the star if the product is built so the model can "cook." This is Hou's fifth AI Eng talk; he's built dev tools since 2022.
  • Primitive timeline (one era per year, each constrained by what contemporary models could handle):
  • 2022 — deterministic autocomplete/chat sidebars (embeddings, rules files, AST parsing; "basically everything inside of that app is deterministic because that's all that the model could really handle");
  • 2024 — agents arrive (MCPs, custom tools, permission systems);
  • 2025 — Antigravity's Agent Manager + parallel agents (skills, hooks, artifacts);
  • 2026 — the agent-teams era (dynamic subagents, sidecar triggers, generative UI).
  • Battle scars (the doctrine has costs; "not right 100% of the time"): giving AI a terminal — "Son of Anton" fears of codebase deletion → models improved, permission-system primitives matured, users built faster and shipped safely; removing chat from Windsurf — users "yelling" about the lost sidebar → multi-step agentic research/execution became the norm.
  • Antigravity 2.0: the agent manager decoupled from the IDE into separate apps (IDE is to agent manager what the debugger was to the IDE — optional, one layer down). Antigravity launched Nov 2025; CLI extracted since; 2.0 launched at Google I/O. The bet: agent orchestration ("agent teams, swarms, software factories") is the next form factor, not the IDE.
  • Dynamic subagents (shipped as agent teams in preview, via /teamwork): the lead agent assembles Avengers-like specialized roles; no two subagents are alike (main agent configures, prompts, seeds on the fly); subagents can run a different model chosen by the main agent, not the user; they run in parallel across sandboxes/remote execution. "As the model gets smarter, your team will become more specialized, more collaborative."
  • Gemini 3.5 Flash (launched April) is credited with unlocking this: "really good at leading teams," faster and cheaper — pushing the Pareto curve of intelligence vs speed vs cost.
  • Hero run (demoed by colleague Varun at Google I/O): a complete OS kernel from scratch, playing Doom — 93 subagents, 12 hours wall-clock, 15,000 requests, 2 billion tokens, under $1,000. Caveat from Hou: nobody will spend that daily; the point is ceiling-demonstration. Also built: a browser-based RAW photo editor and a messaging app (hundreds of subagents, ~half a day each).
  • Eval automation ("where the real magic starts happening"): side-by-side eval analysis (control vs experiment tables) traditionally took "a lot of Jupyter Notebook elbow grease"; researchers automated 90% by asking in natural language — the agent proposes 100 hypotheses for the deltas, assigns one subagent per hypothesis in parallel, maps results back, and generates an interactive UI (dropdowns, filters, segment slicing). Total user input: loading a skills file and asking. What took manual effort now takes minutes.
  • Sidecars: a new long-lived plugin protocol letting the model listen to the outside world and set its own triggers (SMS, webhooks, cron jobs, GitHub PR hooks) — a generic primitive, not a feature set; scheduled tasks are the shipped proof point (cron sidecar); spec promised "later this summer." Strategic significance: agents stop being purely reactive to prompts.
  • Generative UI: "we hypothesize that human written specialized UIs are kind of dead." Enabler: Gemini Flash at ~900 tokens/sec on Antigravity (10x typical frontier experiences) — thought → prompt → purpose-built inline UI in seconds. Examples: Kanban boards, Chrome-debugger-style timelines, charts, tables, Doom. Steve Jobs iPhone-keyboard analogy: fixed controls "are there whether you need them or not" — Antigravity "skipped the heavy infrastructure and mechanical UIs," producing an experience "not fixed in plastic."
  • Model-product flywheel: Antigravity 1.0 (parallel agents, human in the driver's seat) taught Gemini multi-agent management; that capability was imbued into the model, which is what makes 2.0 buildable — causality runs both ways (product teaches model, model enables next product).
  • Builder heuristic to close: ask what primitives your product has and how they scale with model intelligence; shipping features is easy now, choosing which ones is the discipline — so the product is amplified, not obsoleted, by the next (inevitably faster, better, cheaper) model release. Closing joke: reusing the slide until the team has "actually conquered the TPU crunch" — compute supply, not model capability, is the binding constraint he expects to persist.

Notable quotes & data

  • 93 subagents / 12 hours / 15,000 requests / 2 billion tokens / under $1,000 — OS kernel from scratch, running Doom.
  • "We hypothesize that human written specialized UIs are kind of dead."
  • "Flash now isn't just good at executing tasks, it's actually really good at leading teams. It's faster and cheaper, pushing the pareto curve of what is intelligent versus the speed and the cost at which you run those things."

Tokenomics / efficiency angle

  • Explicit token/cost accounting: 2B tokens for <$1,000 on the hero run; Flash selected for the intelligence/speed/cost Pareto frontier; lead agents choose per-subagent models (cost-aware orchestration).
  • Eval-driven iteration at scale: 90% of side-by-side eval analysis automated — 100 hypotheses pursued in parallel by subagents, results mapped back into interactive reports.
  • Compute as the binding constraint: the "TPU crunch" joke flags supply, not capability, as the durable bottleneck.

Local-deploy takeaways

  • Let the lead agent pick per-subagent models, not the user — cost-aware orchestration: route subtasks to the cheapest model that clears the quality bar, reserving frontier models for the lead/planning role. This is the deployable pattern behind the 2B-tokens-under-$1,000 hero run.
  • Treat compute supply as the binding constraint: when capability is no longer scarce, budget and schedule against available inference capacity — the "TPU crunch" lesson applies to local GPU queues as much as Google's fleet.
